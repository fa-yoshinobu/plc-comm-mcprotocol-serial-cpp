# ESP32 / STAMPLC：MC通信の用途別サンプル

FX5Uの内蔵RS-485を使う7種類の例です。各ファイルが独立したプログラムで、共通のUART初期化とエラー処理だけを[common.hpp](common.hpp)へまとめています。MCコアを使うためのアダプターであり、PLC機種の対応範囲やアクセス権限を広げるものではありません。

## サンプルとPLC側のデータ配置

| 環境名・ソース | 読み取り | USBから`w`を送った場合の書き込み |
| --- | --- | --- |
| [word](word.cpp) | D100：WORD、D110～D112：連続WORD | D100=1234、D110～D112=10,20,30 |
| [bit](bit.cpp) | M100、M110～M112：bool | M100=ON、M110～M112=ON,OFF,ON |
| [dword](dword.cpp) | D100～D101：DWORD、符号付き解釈も表示 | 32bit整数123456789 |
| [float](float.cpp) | D100～D101：32bit REAL | 12.5（D100=0000h、D101=4148h） |
| [random](random.cpp) | D100・D200：WORD、D500～D501：DWORD | D100=10、D200=20、DWORD=123456。別要求でM100=ON、M200=OFF |
| [multi_block](multi_block.cpp) | D100～D101、D200～D202、M100～M115 | WORD=10,20／30,40,50。M100とM102をON、残り14点をOFF |
| [async_lcd](async_lcd.cpp) | D100を非同期で読み、公式M5ライブラリでLCD表示 | 書き込みなし。ボタンAを押した回数を表示 |

実際に使用する番地を確認してから例を実行してください。ラダーが同じ番地へ書いていると、サンプルの書き込み値が次のスキャンで変わることがあります。例は元の値を自動復元しません。

## ビルド・実行

このフォルダーをVS Code / PlatformIOで開きます。[platformio.ini](platformio.ini)は同じリポジトリのライブラリを直接参照します。リポジトリのフォルダー名は`plc-comm-mcprotocol-serial-cpp`を想定しており、変更した場合は`lib_deps`の相対パスも直してください。

```powershell
pio run -e word
pio run -e word --target upload --upload-port COM15
pio device monitor --port COM15 --baud 115200
```

COM15は例です。`word`を表の別の環境名へ変更すると、選んだソースだけをビルドします。書き込みは同期6例で、USBモニターから小文字`w`を1文字送ったときだけ実行します。正常な読み取りの後に判定するため、読み取りでエラーになった場合は書き込みません。複数の`w`を送ればその数だけ実行されます。

全例のビルド確認：

```powershell
pio run -e word -e bit -e dword -e float -e random -e multi_block -e async_lcd
```

## 通信条件とメモリ

- FX5U：MCプロトコル、形式5、19200bps、8bit、偶数パリティ、1stop、サムチェックあり、局番0。
- STAMPLC PWR-485：RX=39、TX=0、DIR=46、UART1。`Serial1`やModbusとの同時使用はしません。
- 要求フレーム768、応答フレーム768、要求データ384バイト。`build_flags`でアプリとライブラリの両方へ適用しています。
- Arduinoの標準8KBスタックを使用します。ランダム・複数ブロック機能は有効のままです。

記載した少数点の操作を対象とします。最大点数のマクロが大きくても、実際のフレーム容量を超える要求は通りません。点数を増やす場合は応答容量・エスケープによる増加・スタック残量も確認してください。

## 型と結果の読み方

WORDは`uint16_t`、DWORDは`uint32_t`です。通常のDレジスタでは32bit値の下位ワードが先頭番地、上位ワードが次の番地になります。DWORD例では専用アイテムを使うため、結合・分解をコアが行います。

floatは同じ32bitのビット列を`memcpy`で移します。数値キャストすると別の値になります。PLC側も同じ2ワードをREALとして格納してください。`12.5f`のビット列は`0x41480000`です。

ランダム読み取りではWORD配列とDWORD配列を分け、指定順に値が入ります。ビットのランダム書き込みは独立したコマンドです。複数のAPI呼び出しをまとめて確定する仕組みはありません。

複数ブロック読み取りは、WORD出力・ビット出力・ブロック結果の3配列を使います。結果には各ブロックの出力位置と数が入ります。ビットブロックの`points=1`は16ビットを意味し、`bool`1要素ではありません。

## エラーと非同期処理

どの例も、成功を確認してから値を使用します。通信エラー時は通信を停止してUSBへ原因を表示します。配線・条件を修正した後にRESETで再開します。実行結果が不明な書き込みを勝手に再送しません。

同期6例は説明を短くするため、応答待ちと1秒間隔の待機を使います。画面や入出力を動かし続けるアプリの参考には`async_lcd`を使用してください。`plc.update()`と`M5StamPLC.update()`を毎周回呼び、通信エラー後もボタン操作を続けます。受信先とコールバック用の状態は完了まで有効な領域に置き、コールバック内から新しい要求を開始しません。

詳しいAPI仕様は[UARTアダプターの説明](../../docsrc/user/ARDUINO_ESP32_UART.md)を参照してください。
